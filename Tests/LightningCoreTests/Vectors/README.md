# Independent Lightning vectors

BOLT 3 Appendices C/D (including all nine shachain storage cases) and BOLT 8 Appendix A, extracted from lightning/bolts revision 1aadb719b4007c4cea0ba6e36b08c4fb53788dee.

https://github.com/lightning/bolts/tree/1aadb719b4007c4cea0ba6e36b08c4fb53788dee

Copyright the BOLT authors; Creative Commons Attribution 4.0 International (https://creativecommons.org/licenses/by/4.0/). These files reformat published vectors as JSON; they do not change expected results. All keys are published synthetic test data.

BIP143 vectors: Johnson Lau and Pieter Wuille, Public Domain. Nine examples covering P2WPKH, P2SH-P2WPKH, all six P2SH-P2WSH sighash modes and the first No FindAndDelete example. Extracted from https://github.com/bitcoin/bips/blob/master/bip-0143.mediawiki (source SHA-256 62bc71351563e68baeb12643c68355d217953ae9eb6a6e68b2b0323275b6beec).

`cln-onion.json` was generated by the unmodified Core Lightning v26.06.8
`createonion` RPC at commit `6f741afc395c66d200429ea477d29df4d974748d`.
`scripts/ci-lightning-peer` regenerates it from public disposable keys and
three explicitly supplied payloads, including a payload longer than 252 bytes.
The packet and shared secrets come from CLN, not the Swift implementation.
The all-zero ChaCha20 stream in `OnionTests` is RFC 8439 Appendix A.1 vector #1.

`BOLT12/{format-string,offers,signature}-test.json` are unmodified upstream
vectors from the same BOLT revision and license above. `ldk-static-invoice.json`
comes from public builders in the pinned LDK reference library. The separate
host harness regenerates it and verifies Swift-built requests and static
invoices through LDK's normal parsers and signature checks. Keys are public,
disposable fixtures; codec acceptance alone is not async payment settlement.

`BIP353/proof-{1...5}.json` preserve the RFC9102 AuthenticationChain bytes from
the primary BIP353 published test vectors. Each file includes its source URL,
human-readable name and the historical validation time (August 7, 2025 noon UTC,
within the published signatures' validity windows). The complete BIP source is
https://github.com/bitcoin/bips/blob/master/bip-0353.mediawiki, authored by Matt
Corallo and Bastien Teinturier. Simple and cross-domain wildcard/CNAME proofs
must authenticate; the two published invalid proofs must fail for ambiguous
payment records and absent wildcard denial evidence. Local synthetic DNAME,
P384 and Ed25519 tests separately exercise supported cryptographic primitives.

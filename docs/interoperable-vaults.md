# Interoperable vaults for Winnow: proposal

Winnow already signs two Taproot policies of its own making. This proposal makes it one party
in the vault setups other wallets and signing devices produce, and lets it import and watch one
made elsewhere. Scope confirmed 2026-10-18: Taproot and P2WSH (`wsh()` multisig and miniscript);
nested `sh(wsh())` stays out unless asked.

## What Winnow has today (origin/main, 0.8.6+)

- Descriptors (`WalletCore/Descriptors/Descriptor.swift`): BIP380 grammar and checksum,
  `tr(KEY)`, `tr(KEY,TREE)`, `rawtr(KEY)`; leaves `pk()`, `multi_a()`, `sortedmulti_a()`; keys as
  hex, WIF or xpub/tpub with `[origin]`, BIP389 `<0;1>` multipath and `/*`; BIP390 `musig()` with
  BIP328 derivation. Nothing non-Taproot, no miniscript, no `pkh()` leaf, no timelocks.
- Script: tapleaf/branch hashing, control blocks, the `multi_a` builder and parser. Opcodes known:
  CHECKSIG, CHECKSIGADD, NUMEQUAL, GREATERTHANOREQUAL. No CLTV/CSV.
- PSBT: v0 and v2 (v0 normalised to v2), BIP371 Taproot fields, BIP373 MuSig2 fields, unknown
  fields preserved. Signer: key path (BIP86) and script path for a `multi_a` leaf only, and only
  the input's FIRST leaf. Finalizer: key path or `multi_a` witness only. Sighash DEFAULT/ALL only.
  v0 export refuses `PSBT_IN_REQUIRED_*_LOCKTIME`; v2 locktime fields are parsed but not honoured.
- Vault (VaultKit): exactly two shapes, `tr(H, (sorted)multi_a(k, xpub/<0;1>/*…))` with the raw
  BIP341 NUMS point `H` as internal key, and `tr(musig(xpub…)/<0;1>/*)`. Any other descriptor is
  refused at import and at launch. Spends are built with sequence `0xFFFFFFFD` and an
  anti-fee-sniping locktime; nothing can set a CSV sequence or a CLTV locktime.
- Exchange: Base64 paste, copy and the share sheet. QR display for addresses and savings cards
  only; no camera, no file import or export, no animated QR, no UR, no BBQr.
- Tests: BIP380/387/390 vectors parsed out of the BIP text, BIP388's Taproot example with its
  miniscript leaf REPLACED by `pk()` (DescriptorTests), descriptor bounds, PSBT round trips, a
  live Bitcoin Core cosigner (`TestSupport/Node/CoreSigner`), fuzz targets `descriptor`, `psbt`,
  `control-block`. The vaults guide already says hardware compatibility is unverified.

## Standards to cover, and what is missing

1. Output descriptors, BIP380 family, with miniscript leaves. Missing: the tapscript miniscript
   fragments (`pk_k pk_h older after sha256 hash256 ripemd160 hash160 and_v and_b andor or_b or_c
   or_d or_i thresh multi_a sortedmulti_a`, wrappers `a s c t d v j n l u`, `0`/`1`), the type
   system (B/V/K/W and the correctness, malleability and timelock-mix properties, as in Bitcoin
   Core's `miniscript.h`), byte-exact script compilation, canonical serialisation, and an
   unspendable-key rule wider than "the raw H hex" (Liana puts H in an xpub with chain code
   `sha256(concat of the tree's xpub keys)` and derives `/<0;1>/*` from it).
2. BIP388 wallet policies. Missing entirely: `tr(@0/**,{…})` templates with a key vector, `/**`,
   the placeholder rules, policy↔descriptor in both directions. Ledger and BitBox02 register these;
   it is also the natural compact form for Winnow's own savings card.
3. PSBT exchange with signing devices. Missing: `.psbt` files (import and export), animated QR
   both ways (UR per BCR-2020-005/006: `ur:psbt`, tag 40310, and the legacy `ur:crypto-psbt`;
   BBQr `B$HP…` from Coldcard), a camera scanner, and the PSBT contents devices expect
   (BIP371 derivation entries with leaf hashes for every signer key, which Winnow already writes
   for `multi_a`; `PSBT_GLOBAL_XPUB` where a device wants it). Also descriptor import over the same
   channels (`ur:output-descriptor`, BBQr `U`/`J` text).
4. Miniscript recovery templates in Liana's style. Missing: satisfaction (choosing a spending path
   from the keys held, the chain height and the coin's age), setting `nSequence` for `older()` and
   `nLockTime` for `after()` on the spend, signing and finalising a leaf that is not `multi_a`, and
   a policy explanation that reads the descriptor ("Owner alone, any time; Heir alone after 52,560
   blocks"), never a label.

## Fixtures, by standard

All fixtures are files committed under `Tests/*/Vectors/` with their upstream source and revision
recorded, as the Vectors READMEs require. None is generated by Winnow.

| Standard | Fixture source | What the test proves |
| --- | --- | --- |
| Miniscript leaves | Bitcoin Core v31.0 `src/test/miniscript_tests.cpp` (97 cases: validity, non-malleability, needs-sig, tapscript-invalid flags, 10 with explicit tapscript hex) and `descriptor_tests.cpp` (`tr()` rows with miniscript leaves and expected scriptPubKeys) | parse, type, compile byte for byte, derive the same P2TR output, refuse what Core refuses |
| Miniscript leaves | BIP388's Taproot example (already in `bip-0388.mediawiki`), its `or_b(pk(…),s:pk(…))` leaf no longer simplified away | engine end to end on the BIP's own expansion |
| Liana templates | Liana `liana/src/descriptors/mod.rs` test descriptors (`tr(OWNER/<0;1>/*,and_v(v:pk(HEIR/<0;1>/*),older(52560)))`, the 3-of-3 decaying to 2-of-3, multi-recovery-path cases) and Liana's unspendable-xpub construction | a Liana wallet imports, derives Liana's addresses, shows Liana's spending paths |
| BIP388 | the BIP's valid and invalid policy vectors (in the repo already) and Ledger `tests/test_e2e_tapscripts.py` policies (`tr(@0/**,multi_a(2,@1/**,@2/**))`, `thresh(3,…,sln:older(12960))`, nested trees) | policy↔descriptor both ways, placeholder rules, what Ledger registers is what Winnow derives |
| PSBT with devices | Ledger `tests/psbt/singlesig/tr-*.psbt` and the tapscript cases' signed PSBTs; Coldcard `testing/data/*.psbt` and the EDGE branch `testing/test_miniscript.py` taproot cases; a Sparrow-exported taproot multisig PSBT | Winnow parses, combines, verifies the device's signatures and finalises; its own PSBT carries the fields the device needs |
| UR and BBQr | BCR-2020-005 fountain and bytewords vectors, the `ur:psbt` example in BCR-2020-006, BBQr spec headers and the `coinkite/BBQr` reference tests | encode→decode round trips, part loss recovery, the reference strings decode to the reference bytes |
| Timelocks on chain | the existing signet fixture: Core creates and co-signs a `older()` recovery spend; the journey or a focused node test mines past the delay and confirms it | the sequence and locktime Winnow sets are what the network accepts |

A fixture from a device proves byte compatibility of parse, compile and signature verification.
It does not prove the device accepts Winnow's PSBT; that stays an unverified claim until someone
records a run with named hardware and firmware, as the roadmap already requires.

## PRs, one commit each

1. `descriptors: miniscript in tr() leaves and wsh()`. A `tr()` leaf or a `wsh()` body is a
   `Descriptor.Leaf`: the four multisig forms Core keeps at the descriptor level, or a
   `Miniscript` node (parser, Core's type system and resource analysis in both script
   contexts, byte-exact compiler, canonical text, Core's sanity gate at the parse). `wsh()`
   derives bech32 addresses; opcodes added to `Script.Op`. Core's vectors in both contexts,
   Core's `tr()` and `wsh()` descriptor rows, BIP382/383, the BIP388 Taproot examples
   unsimplified, Liana's templates with their checksums and one Liana address, the descriptor
   fuzz target. No signing change; a vault still admits exactly its two shapes, and a test pins it.
2. `psbt: satisfy miniscript leaves and timelocks`. A satisfier over the keys held and the chain
   state; `older()`→`nSequence`, `after()`→`nLockTime` on the creator side; Taproot signer and
   finalizer for any typed leaf, not only `multi_a`; honour v2 `PSBT_IN_REQUIRED_*_LOCKTIME`
   instead of refusing. Core's satisfaction vectors and a signet spend after the delay.
3. `psbt: P2WSH inputs`. BIP143 sighash, ECDSA partial signatures (`PSBT_IN_PARTIAL_SIG`),
   `PSBT_IN_WITNESS_SCRIPT`, `PSBT_IN/OUT_BIP32_DERIVATION`, `PSBT_GLOBAL_XPUB`, and the P2WSH
   finalizer over the same satisfier. BIP174's P2WSH vectors, BIP143's vectors, Ledger's
   `wsh-2of2.psbt`, Coldcard's multisig PSBTs.
4. `descriptors: BIP388 wallet policies`. Template and key-vector parsing, the placeholder and
   derivation rules, expansion to a descriptor and the reverse. The BIP's vectors (its `wsh()`
   rows now as written), Ledger's policies.
4b. `vaults: a signed provider card`. The plugin definition a wallet or signing device publishes:
   the existing savings card grown to a BIP388 policy with its key vector, a role per key and the
   paths each key can take, the exchange channels the provider supports, a publisher identity and a
   signature over the card. Verified locally: every address derived from the policy itself, every
   signature checked against the leaf it claims, the publisher key pinned on first use, and
   contributed fixtures (a provider's descriptors and the PSBTs it signed) run in the test suite on
   every build. Nothing a provider says about custody, key independence or off-chain delays is
   trusted or displayed as more than its claim.
5. `vaults: import and watch a policy made elsewhere`. VaultKit's `Policy` grows from two shapes
   to a general policy with named spending paths, Taproot or P2WSH; admission keeps the existing
   rules where they apply (distinct signers, a Taproot key path either unspendable or a declared
   path), the account screen explains each path from the descriptor, watch-only when the phone
   holds no key, cosign when it does. Liana and Sparrow fixtures, the adversarial admission tests.
6. `psbt: files and animated QR`. `.psbt` import and export, UR and BBQr encode/decode with a
   camera scanner and an animated display, descriptor import over the same channels. Spec vectors.
7. Optional: BIP129 BSMS and Coldcard's multisig text, both P2WSH-centric import formats.

## Decisions

- Taproot and P2WSH both in scope; P2WSH signing is PR 3, after the shared satisfier exists.
- Exchange channels: files, UR and BBQr all in PR 6.
- A spendable Taproot key path is accepted when it is a declared spending path and shown as one
  (Liana's single-owner template); the "internal key must be unspendable" rule applies to
  threshold-only policies, where any key path would bypass the threshold.
- Standards first (decided 2026-10-18). A provider framework (capability grants, a coordinator,
  in-process adapters) is not built: a third party cannot ship code into Winnow, so its plugin
  definition is the signed provider card above, and the interfaces such a framework would abstract
  over have one real implementation. Four of its rules ride inside these PRs as tests: admission unchanged until
  the satisfier exists, every spend path enumerated and shown from the descriptor, timelocks
  evaluated in Bitcoin code with reference vectors, and PSBT required-locktime fields honoured or
  refused, never ignored.
- Third parties are wallets and signing devices, not remote cosigning services; no service
  transport or identity is planned.
- VaultKit is a library product another wallet links at the same pinned tag as WalletCore. Every
  PR keeps its public API client-ready: policies, spending paths, admission and import are public
  VaultKit types; PSBT roles stay WalletCore's; nothing from the app or its screens, and no
  app-specific naming, appears in either library. PR 1 adds only public WalletCore types
  (`Descriptor.Leaf`, `Miniscript` and its `Context`, `Fragment`, `Properties`, `Problem`).
- Files before QR in PR 6: `.psbt` import and export first, the animated-QR codecs after.
- The miniscript depth bound is measured, not chosen: a debug build parses 96 nested levels on a
  512 KB thread stack and the bound is 48, far above any real policy.

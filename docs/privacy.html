Winnow Privacy Policy

No account or wallet-history service is required. Winnow includes no analytics, advertising SDK or app-managed crash-reporting service. Public websites, discovery services and the census endpoint still receive ordinary request metadata; this policy does not claim that hosting providers keep no logs.

What the app does with your data

  • Key storage. Seed material is generated on-device and stored in the iOS Keychain with this-device-only protection and a user-presence check the Keychain runs itself before releasing it. Winnow does not automatically transmit it. Recovery displays and exports that you explicitly request can disclose sensitive wallet material; protect those copies.
  • No address leakage by default. The wallet learns its own transaction history by downloading compact block filters (BIP157/158) from random Bitcoin full-node peers and matching them on your device. The watch list is not sent to peers, but block requests, transaction relay and timing can reveal information. Peers see your connection’s IP address.
  • Mempool windows. While the Receive screen is open, the app subscribes to ordinary transaction-relay traffic and matches it locally — the same data every full node sees. Winnow does not send a watch list, but peers and network observers can learn from connection timing, requests and transaction relay.
  • Broadcasting. Signed transactions are relayed to P2P peers over the same direct connections. The transaction itself becomes public when relayed.
  • Receive address labels. Before sharing an unlabeled address, you can name who it is for or what the payment is for, or skip. The note is matched to transaction outputs on this device and stays with that address when you request a new one. It is not a verified sender identity or a return-payment destination. Notes are not included in QR codes, copied/shared addresses, payment cards, or wallet backups. Deleting or replacing the wallet removes its receive address labels.
  • Labels and explorer consent. A received payment can have a persistent local name without an address. Addresses supplied by you and explicitly selected local or explorer suggestions can be attached later. Funding-address suggestions remain unverified; they are not sender identities and reusing them can reduce privacy. Every explorer lookup requires consent explaining the transaction-ID disclosure and that the explorer sees your IP address. A sole result is never selected automatically. Opening an external browser gets a separate warning: the browser shares its own IP address with the site.
  • No Tor or VPN inside the app. Versions 0.6 through 0.7.0 offered an opt-in embedded Tor client; 0.7.1 removed it because its dependencies had not been independently reviewed. Every connection the app makes now comes from your device’s own IP address. Tor and I2P are on the roadmap.
  • Census refresh. Advanced settings downloads a public candidate catalog from census.winnowwallet.com only when requested. This request reveals network metadata to the service (your IP address), but contains no wallet address or transaction ID. Validation failure preserves good data. Refresh does not disconnect active peers; Reset and shuffle peers is a separate action that preserves manual settings and the downloaded catalog.
  • Third-party code. The pinned swift-secp256k1 package supplies Bitcoin cryptography; it is the only third-party dependency. The source repository records its version and the dependency security review.

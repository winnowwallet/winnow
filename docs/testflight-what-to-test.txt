Winnow: fee policy, peer verification and recovery checks

Mainnet scans now require compact-filter checkpoint agreement from at least two known peer acquisition source classes. If verification is unavailable, Settings offers an explicit single-source choice for the current session; relaunching returns to strict verification. Source classes do not prove that peers have different operators.

Automatic peer-driven fee increases now use the majority of configured peer seats and stop at 120 sat/vB. A higher reported floor requires an explicit fee decision. Peer floors are relay hints, not fee estimates or guarantees that a transaction will be accepted.

After updating, check existing wallets, vaults, contact cards, balances, transaction history and payment approvals. Check fee previews, refusals and the session-only verification setting. Use test-network funds for sends and a separate test wallet for backup export and file import. Automatic cloud-backup updates should still work; replacement-device iCloud recovery remains unverified.

The shared library gains account-key signing, durable address cursors, bounded range recovery, recipient metadata, confirmation hashes and relay-only APIs. This build does not add a completed hardware-card or iPhone NFC signing flow. Recording block hashes alone does not validate an imported backup.

Report bugs at https://github.com/winnowwallet/winnow/issues. Include the app version, device, network, routing mode and steps to reproduce. Never include recovery words, private keys or wallet backup files.
